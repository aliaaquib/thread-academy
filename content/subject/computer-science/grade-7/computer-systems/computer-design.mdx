Every digital device — phone, laptop, game console, washing machine — follows the same design: take **input**, **process** it, produce **output**. Learn that pattern and you can evaluate any device's design.

<Definition term="Computer system">
  A combination of hardware and software that takes input, processes it, and produces output.
</Definition>

## Key ideas

### Input → Process → Output

- **Input** — data entering the system: keyboard, mouse, touchscreen, microphone, camera, sensors.
- **Process** — the computer works on the data: calculations, decisions, transformations.
- **Output** — the result leaves the system: screen, speaker, printer, motor, light.

A phone call: microphone (input) → processor handles the sound (process) → speaker at the other end (output). Same pattern everywhere.

- **CPU (processor)** — carries out instructions: the brain. Faster CPU = more instructions per second.
- **RAM (memory)** — temporary workspace holding what the CPU is using now. Emptied when power goes off.
- **Storage (SSD/disk)** — long-term keeping: files, apps, the operating system. Survives power-off.
- **Motherboard** — the board everything plugs into, carrying data between parts.

### Evaluating a design

Good design matches the device's job. A gaming laptop needs a fast CPU and lots of RAM; a fitness tracker needs tiny size and long battery, so it accepts a slow processor. Evaluating design means asking: *is each part right for what this device must do?*

### Designing for a real user: the details matter

When designers choose a device's features, they think about one **aspect of the design** at a time — a single part or feature — and justify it against the user's needs. Typical features on the checklist:

Small screen, lightweight body, speaker, microphone, touch screen, on/off button, volume control, fingerprint sensor, Bluetooth capability, hard outer case, camera.

Example — designing a phone for a busy commuter:

- **Lightweight** — it will be carried around a lot, so it must not be too heavy.
- **Large screen** — the user reads emails and social media, so a big screen improves that experience.
- **Good quality speaker** — the user makes calls in noisy places (like a train), so they need to hear the other person properly.

Each feature is justified by what the user actually does — that is what evaluating a design means in practice.

<WorkedExample title="Evaluate two designs">
  Device A: a video-editing desktop — fast CPU, 32 GB RAM, huge SSD. Device B: an e-book reader — slow CPU, 1 GB RAM, small storage, weeks of battery.

  A edits 4K video: the fast CPU chews through effects, RAM holds the footage, storage keeps projects. B shows static text: a fast CPU would only drain the battery for nothing.

  **Answer:** Both are well designed — because design is judged against purpose, not raw power. A's power fits video; B's restraint fits reading.
</WorkedExample>

<ImportantNote title="Common mistakes">
  - **RAM = storage** Correction: RAM is temporary workspace (emptied at power-off); storage keeps files long-term.
  - **Faster is always better** Correction: design is judged against purpose — a tracker does not need a gaming CPU.
  - **Forgetting software** Correction: a computer system is hardware + software; parts alone do nothing without programs.
</ImportantNote>

## Practice

<PracticeQuestions>
  <PracticeItem question="A barcode scanner beeps and shows a price. Identify the input, process and output.">
    Input: the scanned barcode. Process: looking up the price. Output: the beep and displayed price.
  </PracticeItem>
  <PracticeItem question="Why does unsaved work vanish when the power cuts out?">
    It was in RAM, which is temporary — power off empties it. Only saved files reach long-term storage.
  </PracticeItem>
  <PracticeItem question="A school buys tablets for note-taking. Which matters more: a huge SSD or long battery life?">
    Battery life — notes are tiny files, but a dead tablet mid-lesson is useless. Design follows purpose.
  </PracticeItem>
  <PracticeItem question="What connects the CPU, RAM and storage together?">
    The motherboard — the board everything plugs into, carrying data between parts.
  </PracticeItem>
  <PracticeItem question="What is meant by 'an aspect of the design'?">
    A single part or feature of the device's design — e.g. its weight, its screen, its speaker — considered one at a time.
  </PracticeItem>
  <PracticeItem question="A designer chooses a large screen for a commuter's phone. Justify the choice.">
    The user reads emails and social media, so a large screen improves their experience of doing this.
  </PracticeItem>
  <PracticeItem question="Why might the same commuter also need a good quality speaker? Justify it.">
    They make calls in noisy conditions such as a train, so they need a good speaker to hear the other person properly.
  </PracticeItem>
</PracticeQuestions>
